# v0.6：同步算法升级与测试

日期：2026-09-29。基于 v0.5.0 的 C++20 + Win32 实现，交付 Windows x64 可执行文件。此文记录已经落地的行为；此前的完整预案保留在 [SYNC-ACCURACY-UPGRADE-PLAN.md](SYNC-ACCURACY-UPGRADE-PLAN.md)。

## 本版实现

1. 新增用户指定的 `ntp.ntsc.ac.cn`、`ntp.cnnic.cn`、`cn.pool.ntp.org`，并加入 Canonical、NTP.br、Netnod 备选。全新配置共 12 个域名、10 个名义来源组；实际端点重合会进一步减少独立计数。
2. 低延迟历史过滤、明确故障预算的闭区间选择、按路径稳健频率估计与共同 QPC 纪元投影。
3. 默认在 T−180 秒开始精校准，T−60 秒结束并冻结。显示进度、样本数和失败状态，提供 GUI 开关。
4. 增加原始观测和模型日志、可重复的网络观测入口与分析工具。

自动预约、默认左键、按下/保持/释放、每小时重复、窗口位置、置顶和精简模式保留。调度继续使用内部 QPC 映射；已有系统时间写回偏好保留，可自行关闭。升级不会把“内部时钟”理解成强制取消用户要求的系统校时功能。

## 来源发现和优选

常用来源最小间隔 10 秒；Pool、Canonical、NTP.br、Netnod 使用 64 秒。最多 6 个并发请求。精校准的有效间隔为 `max(每源最小间隔, RefinementPollSeconds)`，不会把允许 10 秒一次的服务器当成可连续发送毫秒级突发请求的服务器。

同 IP/端口在发送前去重；因限速或共享端点延后的查询不计为失败。运营商别名合组，不能通过修改分组字符串让已知同一运营商获得额外票数。DNS 中仍存在的健康地址会继续使用；连续失败后轮换其他解析地址，最终版本按稳定次序遍历地址，避免只在前两个地址之间循环。

推荐顺序只影响初次发现，主用顺序由质量评分决定：可行区间、网络时延、上游误差、抖动、样本年龄和失败记录。偏差接近本机时间不作为准确性依据。

Pool 是动态节点集合，与其他运营商来源可能重合，不能视为独立授时机构；目前只能合并已知运营商和实际相同端点，不能证明其共同上游或网络路径独立。本次按用户要求启用中国区 Pool。若将软件大规模分发，应按 NTP Pool 的 [厂商接入说明](https://www.ntppool.org/vendors.html) 申请专用区域，避免将公共区域作为大规模客户端的固定默认值。

来源资料：

- [国家授时中心官网](https://www.ntsc.ac.cn/)；`ntp.ntsc.ac.cn` 为用户指定，本次完成 DNS/UDP 验证。
- [CNNIC 官网](https://www.cnnic.cn/)；`ntp.cnnic.cn` 为用户指定，本次完成 DNS/UDP 验证。
- [NTP Pool 中国区](https://www.ntppool.org/zone/cn)。
- [Ubuntu 官方 timesyncd 文档](https://documentation.ubuntu.com/server/how-to/networking/timedatectl-and-timesyncd/)，列出 `ntp.ubuntu.com`。
- [NTP.br](https://ntp.br/)，列出公开服务 `a.ntp.br`。
- [Netnod 免费时间服务](https://www.netnod.se/free-time-services) 与 [服务器接入说明](https://www.netnod.se/ntp/connect-to-ntp-servers)。

官方机构身份、一次可达或较低 RTT，都不等同于已经独立验证 UTC 精度。未获得 NTSC/CNNIC 明确的服务时延或精度保证；服务端限速及拒绝响应仍按协议处理。

## 估计器和误差范围

### 原始采样与路径过滤

- 每次请求使用固定启动基准与 QPC 生成客户端时间戳，避免中途系统校时污染同一次四时间戳测量。
- 取消、锁和端点预算检查位于发送时间戳之前，记录发送和接收 QPC。最终版本把相位观测挂在交换中点时刻，避免把整个交换的相位直接当作接收时刻相位。
- 以实际 IP/端口保留路径历史，最多 256 个样本、30 分钟。间断超过 300 秒清除该路径历史；电源/会话中断也清除学习状态。
- 常规相位窗口 180 秒，精校准窗口 120 秒。精校准阶段已有至少 3 个新样本时使用本阶段数据，否则暂用近期历史暖启动。
- 投影公式为 `offset(now) = offset(sample) + ageSeconds × ppm / 1000`，区间按年龄和频率裕量向外扩展；同一路径区间冲突则拒绝该路径。
- 点估计使用低延迟且较新的子集的中位数；区间、点估计和抖动分别维护，不把样本数直接换算成更小误差。

### 容错区间

每条路径的观测半径包含 RTT/2、上游误差和工程时间戳裕量。运营商代表形成闭区间后，采用 Marzullo 类端点扫描：默认 `f=1`，在 `n ≥ 2f+1` 时保留至少 `n−f` 个区间覆盖的区域。

多个互不相连的可行区域意味着无法判断，拒绝更新；来源不足时明确降级为 `f=0`。这是一种有前提的故障模型，并非认证来源。错误组超过预算、来源有关联或诚实区间本身未覆盖真值时，不具备覆盖保证。

点估计仍可偏重最多三个低评分来源，但最终误差必须包住整个容错可行区域，不能在质量裁剪后只采用最窄来源的误差。这修复了旧版“加入一个自报极低延迟的错误来源后，误差条缩小约 200 倍”的反例。

### 稳健频率与冻结预测

每路径先筛掉高排队时延，再以点对斜率中位数初始化，进行 5 次 Huber 加权回归。至少 8 个合格样本且跨越 120 秒才产生初步拟合；至少 16 个且跨越 300 秒才视为成熟。频率估计限制为 ±200 ppm。

频率裕量综合残差、时间跨度和前后半段斜率差异，保留 2 ppm 下限，不按 `sqrt(N)` 缩小。每运营商一个频率代表，再按区间规则融合。满足故障数量条件，且至少 `max(2, 2f+1)` 组成熟后，才允许把默认 30 ppm 裕量调低。

保持期间的误差按模型年龄线性增长。上述裕量是工程估计，不是有统计覆盖率认证或独立硬件标定的物理上界。最终版本未引入卡尔曼滤波、NTS、网络硬件时间戳、接口级路径识别或完整闰秒/闰秒平滑策略。

## 精校准与冻结

```text
自动发现/跟踪 → T−180 秒精校准 → T−60 秒冻结 → 按下/保持/释放 → 恢复同步并预约下一小时
```

精校准进度仅表示该时间窗口已经经过的比例，不表示精度达标。它是一段聚焦于近期低延迟数据的准备流程；在当前公共源速率限制下，不额外发送超限突发包。若第一次设定任务时距离点击不足 60 秒，沿用现有冻结规则，不把点击延后等待精校准。

手动停止同步始终优先。模型提交前再次检查冻结边界；冻结期间不应用晚到响应，也不写回系统时间。执行使用被冻结的 QPC 截止时刻。

## 验证结果

### 合成与状态测试

- 最终 Windows x64 构建完成，133 项检查全部通过；编译未产生警告。
- 2,000 个可重复随机单故障案例：1,739 个得到唯一可行区间并覆盖已知真值，261 个报告多解；没有把多解当作成功结果。
- 旧版窄错误来源反例：真偏差 0、测得中点 +6 ms；新版保留至少 ±10.05 ms 的范围，不会缩小到 ±0.05 ms。
- 已知 30 ppm 漂移且有排队尖峰的合成路径：估计约 30.0006 ppm；保留 2 ppm 裕量；60 秒预测误差约 0.010 ms。该数字仅对应合成数据，不能作为公网精度宣传。
- 测试覆盖端点去重、重复样本、过期与冲突路径、精校准采样和进度、暂停/恢复、配置持久化、冻结后的模型不变与禁止系统校时。
- 真实 GUI 自测在本地模拟 NTP 上完成：一次 F8 down/up，保持约 19.43 ms，准备提示一次，执行后恢复同步、下一小时预约、实际重启恢复均通过。测试只向自己的前台窗口输入。
- 隔离 GUI 检查普通/设置/精简模式切换、新增开关、来源列表、状态栏和无残影重绘。正式用户配置与系统时间未修改。

此外，正式六分钟观测前的一轮查询中 Pool 曾返回有效结果，RTT 约 201.16 ms。Pool 的地址会变化，六分钟中的去重不是将其判为不可用。

约 312 秒时频率模型达到成熟条件，最终估计 9.66 ppm，学习的裕量 7.93 ppm，对应冻结 60 秒增加约 0.476 ms 的工程预算。最终整体相位误差预算仍约 ±31.83 ms，网络与故障区间主导了范围，不能把频率裕量改善等同于已经达到 UTC ±1 ms。

六分钟观测使用本轮开发版，随后又修正了交换中点纪元和失败地址完整轮换，并补做最终构建验证及一轮公共源查询。最终单轮中 Pool RTT 约 239.02 ms、NICT 63.45 ms、阿里较快节点 36.10 ms；NTSC/CNNIC 的首选地址未在该轮响应，长时间运行仍按失败轮换机制寻找可用地址。这再次说明不能用单轮结果固定排名。没有独立 UTC 参考，所以此测试用于验证可达性、延迟、去重和学习流程，不证明真实 UTC 误差，也不宣称算法一定比 v0.5 更接近 UTC。

## 复现和升级

```powershell
./scripts/build.ps1 -ExecutableName Ctimer-v0.6.0.exe
./build/CtimerTests.exe --observe 360
python ./scripts/analyze-ntp-log.py ./build/ntp-observation-实际输出编号
./scripts/package-release.ps1 -ExecutablePath dist/Ctimer-v0.6.0.exe
```

分析脚本使用 Python 标准库，运行 Ctimer 本身不需要 Python。`build/estimator-validation.json` 保存合成结果；观测目录包含原始采样、模型 CSV 和 summary.json。日志可用于进一步回放研究，本版未交付完整离线重建所有历史模型的回放器。

更新时关闭旧程序后替换 exe，保留原有 Ctimer.ini。v0.6 为旧配置创建 `.before-v0.6.bak` 并补齐新来源，不覆盖已有源参数或禁用状态；目录容量仍为 24 项。便携包中的 `Ctimer.example.ini` 是示例，不覆盖个人配置。
